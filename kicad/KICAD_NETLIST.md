# WorkBoy controller — KiCad netlist & pin map

Generated by [`generate_workboy_netlist.py`](generate_workboy_netlist.py) →
**[`workboy.net`](workboy.net)** (KiCad "export version E" netlist, 131
components / 89 nets / 309 pin-nodes).

This is "schematic as code": editing the Python and re-running it regenerates the
netlist deterministically. Import `workboy.net` into KiCad's PCB editor to place
footprints + ratsnest, then lay out and export Gerbers + CPL for JLCPCB.

## 1. ATmega328P-AU (U1) pin assignment — also the firmware GPIO map

> Requires fuses set for the **internal 8 MHz RC oscillator** so PB6/PB7 (XTAL)
> are free as GPIO.

| Pin | Port | Net | Function |
|---|---|---|---|
| 1 | PD3 | ROW3 | matrix row 3 |
| 2 | PD4 | ROW4 | matrix row 4 |
| 3 | — | GND | ground |
| 4 | — | +5V | VCC |
| 5 | — | GND | ground |
| 6 | — | +5V | VCC |
| 7 | PB6 | NET_PB6 | LED2 (CAPS) drive → R8 |
| 8 | PB7 | NET_PB7 | LED3 (NUM) drive → R9 |
| 9 | PD5 | ROW5 | matrix row 5 |
| 10 | PD6 | ROW6 | matrix row 6 |
| 11 | PD7 | ROW7 | matrix row 7 |
| 12 | PB0 | COL6 | matrix col 6 (input + pull-up) |
| 13 | PB1 | — | **spare / test point** |
| 14 | PB2 | nSS | SPI /SS — strapped low via R2 (always-selected slave) |
| 15 | PB3 | MCU_MOSI | SPI MOSI ← GB SO via R5 (we sample) |
| 16 | PB4 | MCU_MISO | SPI MISO → GB SI via R4 (we drive) |
| 17 | PB5 | MCU_SCK | SPI SCK ← GB SC via R6 |
| 18 | — | +5V | AVCC |
| 19 | ADC6 | — | unused (analog-only pin) |
| 20 | — | AREF | AREF → C4 to GND |
| 21 | — | GND | analog ground |
| 22 | ADC7 | — | unused (analog-only pin) |
| 23 | PC0 | COL0 | matrix col 0 |
| 24 | PC1 | COL1 | matrix col 1 |
| 25 | PC2 | COL2 | matrix col 2 |
| 26 | PC3 | COL3 | matrix col 3 |
| 27 | PC4 | COL4 | matrix col 4 *(also SDA — no I²C in this build)* |
| 28 | PC5 | COL5 | matrix col 5 *(also SCL)* |
| 29 | PC6 | nRESET | reset — R1 pull-up + ISP |
| 30 | PD0 | ROW0 | matrix row 0 |
| 31 | PD1 | ROW1 | matrix row 1 |
| 32 | PD2 | ROW2 | matrix row 2 |

**Result:** rows = **all of PORTD** (PD0–7 = ROW0–7); cols = **PC0–5 + PB0**
(COL0–6); status LEDs = PB6/PB7; SPI link = PB2–5; reset = PC6. Zero spare digital
GPIO except PB1. *(For an I²C battery-backed RTC, drop to a 7×7 matrix to free
PC4/PC5 for SDA/SCL — see BUILD_PLAN §3.3.)*

## 2. Matrix wiring & diode orientation

8 rows × 7 cols = 56 cells, **53 populated** (the 3 empty cells are row3/5/7 × col6).
Per key:

```
ROWr ──[ SWk ]── KEYk ──[ Dk cathode | anode ]── COLc
        (pin1)  (pin2)   (pad1)        (pad2)
```

- **Scan direction:** firmware drives one ROW **LOW** (others hi-Z), reads COLs
  with internal pull-ups; a pressed key pulls its column low (≈0.7 V through the
  diode — a valid logic LOW at 5 V). One **1N4148W per key** blocks ghosting →
  full N-key rollover.
- **Diode polarity (important):** anode (pad 2) → COLc, cathode (pad 1) → switch →
  ROWr. If you ever flip the firmware to drive columns / read rows, reverse every
  diode. Verify this orientation during layout review — it's the one easy-to-miss
  thing.

## 3. Power & link nets

- **VBUS** (USB-C A4/B4/A9/B9) → **D54** SS14 (anode) → **+5V** (cathode). USB-C
  CC1/CC2 → 5.1 kΩ (R10/R11) → GND (5 V sink). No LDO — the AVR is 5 V-native.
- **Link J1:** 2=LINK_SO→R5→MOSI, 3=LINK_SI→R4→MISO, 5=LINK_SC→R6→SCK, 6=GND.
  Pins 1 (VCC) and 4 (SD) are intentionally **No-Connect** (the two single-node
  nets the generator reports). Don't power from link VCC.
- **ISP J2** shares MCU_MISO/MCU_SCK/MCU_MOSI/nRESET with the link SPI →
  **program before attaching the link cable.**

## 4. Footprints to verify before ordering

Most footprints are standard KiCad libraries and will auto-assign on import. Two
need a manual check:

- **J3 USB-C (C165948):** the script uses GCT `USB4085` pad names (A1…B12, S1–4).
  Confirm against the actual C165948 footprint and remap if its pads differ.
- **J1 GB EXT link connector:** there is **no catalog part**. The placeholder is a
  1×6 2.54 mm header for a cut-cable pigtail. Swap for your chosen breakout/edge
  footprint. Consign it or hand-solder — it's excluded from the JLCPCB BOM.
- **SW (C720477) / tact 6 mm:** confirm the chosen footprint's pad numbering is
  1/2 (some 4-leg tacts net-tie pad pairs — KiCad handles it, just verify).

## 5. Workflow: netlist → board → JLCPCB

1. (Optional) tweak the design in `generate_workboy_netlist.py`, re-run:
   `python generate_workboy_netlist.py`.
2. **KiCad → PCB Editor (standalone)** → `File ▸ Import ▸ Netlist…` → select
   `workboy.net` → *Update PCB*. Footprints drop in with the ratsnest.
3. Assign/verify footprints for J3 and J1 (§4). Run DRC.
4. **Lay out** ~140×85 mm, SMT on top, the 8×7 switch grid at ~10 mm pitch,
   mounting holes for the case. Pour GND on the bottom.
5. `File ▸ Fabrication Outputs ▸ Gerbers` (RS-274X) and **Component Placement
   (CPL/centroid)** → rename columns to JLCPCB's `Designator, Mid X, Mid Y,
   Rotation, Layer` (mm). Pair with [`../workboy_jlcpcb_bom.csv`](../workboy_jlcpcb_bom.csv).
6. Upload Gerbers + BOM + CPL to JLCPCB (Economic PCBA, SMT only; hand-solder the
   53 switches + link pigtail).

> Prefer a drawn schematic instead of a code netlist? The same component/net data
> can be re-expressed in **SKiDL** (`pip install skidl`) to emit a KiCad netlist,
> or you can draw the schematic by hand using this pin map as the spec. The
> netlist route above is the fastest path to a layout.
